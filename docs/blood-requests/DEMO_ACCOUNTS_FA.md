# کاربران و نقش‌های ST-03 — درخواست خون

حساب‌های ST-02 بدون تغییر باقی می‌مانند. مرکز همه حساب‌های آزمایشی، بیمارستان آزمایشی HEMO است.

| نام کاربری | نقش | مجوز |
|---|---|---|
| hemo.nurse | پرستار | انتخاب پذیرش، فهرست و جزئیات درخواست‌های مرکز، ثبت درخواست پرستاری، ویرایش/ارسال/لغو درخواست متعلق به همان کاربر و نقش؛ بدون تأیید پزشک |
| hemo.doctor | پزشک | مشاهده درخواست‌های مرکز، ثبت مستقیم پیش‌نویس پزشک، ویرایش/ارسال/لغو درخواست خود، تکمیل نظر پزشک و تأیید/رد/برگشت درخواست ارسال‌شده |
| hemo.bloodbank | کارشناس بانک خون | فقط صف و جزئیات درخواست‌های تأییدشده؛ بدون ویرایش یا صدور فرآورده |

نقش کارشناس پذیرش، مسئول پذیرش و مشاهده‌گر ST-02 به صورت خودکار مجوز درخواست یا تصمیم پزشک دریافت نمی‌کنند. مجوزهای عملیاتی به APIهای مجزا متصل هستند؛ حتی نقش ادمین برای اقدام بالینی نیاز به اعطای صریح مجوز دارد. در این مرحله محدوده سازمانی، مرکز نقش جاری است؛ تخصیص پزشک به بیمار یا محدودیت ریزتر بخش نیازمند سیاست بیمارستان است.

## فعال‌سازی در PowerShell
ابتدا تنظیمات ST-02 و رمزهای حساب‌های آن را طبق docs/admission/DEMO_ACCOUNTS_FA.md انجام دهید (برای حساب‌های موجود رمز دوباره لازم نیست). سپس:
```powershell
$env:ASPNETCORE_ENVIRONMENT = 'Development'
$env:HemoSeed__Enabled = 'true'
$env:HemoSeed__IncludeBloodRequests = 'true'
$env:HemoSeed__Passwords__Nurse = Read-Host 'Password for hemo.nurse'
$env:HemoSeed__Passwords__Doctor = Read-Host 'Password for hemo.doctor'
$env:HemoSeed__Passwords__BloodBank = Read-Host 'Password for hemo.bloodbank'
dotnet run --project web/web.csproj --no-launch-profile
```
رمز هر حساب جدید متفاوت و حداقل ۱۶ کاراکتر. هیچ رمز ثابت در Git نیست. حساب‌های موجود بازنویسی نمی‌شوند؛ فعال‌سازی فقط در Development و روی دیتابیس آزمایشی. اگر OTP شرکت فعال است، شماره آزمایشی مجاز مطابق رویه شرکت تنظیم شود. حذف فلگ IncludeBloodRequests فقط اجرای Seed جدید را متوقف می‌کند و حساب‌های قبلاً ایجادشده را حذف نمی‌کند. در تولید، مجوزها توسط مدیر از RoleAccess/MenuApi موجود تخصیص داده شوند.
