# راه‌اندازی دسترسی و داده اولیه پذیرش
زیرساخت Identity و Seed اصلی شرکت به دستور مالک پروژه تغییر نکرده است.

1. در محیط آزمایشی شرکت پس از build و migration، فهرست API سامانه را با روش موجود ثبت API (OpenAPI/ApiService) دریافت کنید. مسیرها و HTTP methodها در HEMO_ADMISSION_ACCESS_MANIFEST.json آمده‌اند. در این مرحله Gateway یا Subsystem جدیدی ایجاد نمی‌شود.
2. از مدیریت منوهای موجود، منوی غیرعمومی با routerLink=/admission ایجاد کنید؛ اگر منو موجود است دوباره ثبت نکنید.
3. با مدیریت MenuApi موجود، APIهای موردنظر را به منو متصل کنید.
4. مدیر مجاز از RoleAccess موجود برای نقش پذیرش مجوز بدهد. ApiGUID=null یعنی تمام APIهای map شده منو (طبق الگوی موجود)؛ مجوز مستقیم ApiGUID فقط همان API را اجازه می‌دهد. اعطای دسترسی به نقش‌های غیرپذیرش خودکار نیست.
5. یک کاربر آزمایشی را به مرکز و نقش موجود تخصیص دهید. اطلاعات واقعی بیمار را seed نکنید؛ پرونده آزمایشی مصنوعی را از رابط پذیرش در دیتابیس آزمایشی ایجاد کنید.
6. در فرانت نقش را انتخاب و دسترسی Stats و فهرست را بررسی کنید. Endpointهای جدید به‌طور مستقیم از همین مدل مجوز استفاده می‌کنند؛ بدون تغییر مکانیزم عمومی یا اعتماد به header مسیر صفحه.
7. پیش از اعمال migration، backup دیتابیس آزمایشی و سپس dotnet ef migrations script / database update مطابق تنظیمات فعلی پروژه. تست‌ها ابتدا در دیتابیس غیرعملیاتی.
