# API ST06
Base: /Identity/Hemovigilance. Bearer + UserRole، مرکز جاری، grant صریح.
- GET Capabilities؛ POST List و Stats با HvFilters؛ GET Detail/{guid}، POST Candidates (حواله شروع‌شده فاقد پرونده باز)، GET Owners (کاربر مجاز فعال مرکز).
- POST Report: TransferGuid, TransferVersion, ClientReportId, OnsetAt (offset ISO), Symptoms[], InitialSeverity, Notes, ActionsTaken, SamplesSent, VolumeMl. Idempotency برای همان ثبت‌کننده و حواله؛ فقط پرونده باز واحد. نگرانی روی ST05 ثبت می‌شود؛ توقف فیزیکی یا خودکار نیست.
- POST Observe/DoctorReview/BankReview/Investigate/ReturnToDoctor/PublishRca/Close/External: ReviewInput با Guid/Version/Notes و فیلدهای نقش (HvContracts.cs). رویدادها append-only و زمان UTC. بازگشت برای پزشک، داده‌های جاری بررسی را پاک می‌کند ولی نسخه قبلی در رویدادها می‌ماند. پس از تخصیص CAPA بازگردانی مسدود است.
- POST AssignCapa: Guid/Version/Title/Kind/OwnerUserGuid/DueAt/Indicator. POST CapaProgress/CapaVerify/CapaReject: شناسه و نسخه CAPA، نسخه پرونده، Progress/Evidence. مسئول اجرا گزارش پیشرفت ثبت می‌کند؛ 100% به Submitted می‌رود، نه تأیید. بازبین مستقل قبول یا رد می‌کند. در صورت رد، مسئول اجرا دوباره گزارش می‌دهد. CapaReject همان مجوز CapaVerify.
- POST Archive: Title/From/To/Ward/ProductCode؛ سرور snapshot تجمیعی بدون نام بیمار ذخیره می‌کند. POST Reports و GET ReportDetail/{guid}، POST ReportExternal با Guid/Version/Status/Reference. SentManually فقط ثبت مرجع ارسال انجام‌شده خارج سامانه، نه ارسال شبکه. گزارش‌ها بر مبنای زمان بروز و شروع تزریق جدا هستند؛ نرخ بروز محاسبه نمی‌شود.
- بسته شدن: تصمیم مستند عدم نیاز RCA یا انتشار RCA با همه CAPAهای تأییدشده، تعیین تکلیف گزارش خارجی و بازبین مستقل؛ اگر حواله در حال تزریق است بسته نمی‌شود. زمان/طبقه‌بندی/درجه/اقدام بالینی صرفاً ثبت مستند متخصص؛ بدون استنتاج یا پیشنهاد درمانی. قالب رسمی/امضای قانونی/اتصال INHS نیازمند تأیید.
