# R03 — تست HTTP ایزوله و پذیرش عملی
مبنای نسخه: backend main 0847c93a / frontend main d513ef5d. توسعه و merge R02 کامل است؛ این مرحله برای کشف ایرادهای اجرایی و پذیرش محیط آزمایشی است.

## مرحله اول: HTTP واقعی با SQL ایزوله
IsolatedHttpAcceptanceTests از کلاس‌های Endpoint واقعی web، Kestrel روی IP loopback و پورت آزاد، ثبت سرویس‌های Application/MediatR و Validatorهای واقعی، SQL Server و Migration و Seed کامل R02 استفاده می‌کند. رمزهای Seed و کلید امضای JWT فقط در حافظه تست و تصادفی هستند. توکن با UserService.SetTokenKey در رجیستری واقعی ثبت می‌شود؛ صدور JWT با کلید آزمایشگاهی است و Login/Captcha/OTP شرکت شبیه‌سازی نمی‌شود. Interceptor ممیزی آزمایشی جایگزین وابستگی Mongo/Log شرکت است؛ DispatchDomainEventsInterceptor واقعی حفظ شده. Exception handler موجود و کنترل‌های HEMO اجرا می‌شوند. Startup شرکت، زیرساخت مشترک، Dapper، اتصال به سرویس‌های بیرونی و middleware اختصاصی شرکت اجرا نمی‌شوند.
- شش endpoint Capabilities بدون Token باید 401 بدهند؛ JWT منقضی، TokenKey نامعتبر و Claim انقضای گذشته رد شوند.
- مدیر آمار هفت aggregate را دریافت کند؛ هفت درخواست فهرست و دو جزئیات رد شوند. CheckPagePermission برای داشبورد مجاز و پذیرش جدید غیرمجاز است. Header نقش خارج از Claim رد می‌شود.
- پذیرش مصنوعی: ایجاد، خواندن، ثبت تطبیق هویت، رد RowVersion قدیمی، ثبت سوابق، رد شماره پرونده تکراری.
- درخواست خون مصنوعی: ثبت پرستاری، ارسال، تأیید پزشک و خواندن توسط بانک خون.
- فقط Connection String آزمایشی loopback پذیرفته می‌شود؛ نام دیتابیس یکتا و بعد از تست حذف می‌شود. هرگز به DB شرکت اشاره نکند.
- CI موجود GitHub Actions، SQL Server 2022 موقت را آماده می‌کند. اجرای مستقل:
```bash
dotnet test tests/Hemo.Admission.Tests -c Release --filter "FullyQualifiedName~IsolatedHttpAcceptanceTests"
```
پیش‌نیاز HEMO_TEST_SQL با مقصد localhost و SQL Server آزمایشگاهی است. نتیجه این تست در PR ثبت می‌شود؛ قبل از مشاهده CI موفق، PASS محسوب نمی‌شود.

## مرحله دوم: پذیرش مرورگر در محیط شرکت
نسخه‌های سازگار main و دستور نصب در R02_FINAL_DEPLOYMENT_FA.md. پیش از اجرا، مقصد DB و سرویس‌ها باید توسط مالک زیرساخت تأیید و ایزوله شوند؛ از حساب‌ها و داده‌های ساختگی استفاده شود. هیچ Seed آزمایشی در Production اجرا نشود.
| سناریو | معیار پذیرش |
|---|---|
| ورود/خروج/Captcha/OTP | رفتار واقعی شرکت، نشست و نقش صحیح، کنترل refresh و 401 |
| منو و ۶۲ مسیر | صفحات مجاز، deep link، عدم نمایش رکورد یا عمل غیرمجاز |
| پذیرش و درخواست | گردش مثبت و رد نسخه قدیمی، ثبت تکراری، خروج/تغییر نقش |
| بانک، تجهیزات و تزریق | ارتباط واحد و تجهیز، توقف فنی، شاهد مستقل، مرجوعی و پایش |
| واکنش و کیفیت | بازبینی مستقل، RCA، CAPA، QC، مصوبه و گزارش دوره‌ای |
| گزارش‌ها | محدوده مرکز، عدم افشای جزئیات مدیر آمار، CSV و چاپ |
| مچ‌بند و خدمات بیرونی | چاپگر واقعی و قرارداد تأییدشده HIS/SMS/سرویس‌های لازم |
هر نتیجه با Commit هر دو مخزن، نقش، زمان، داده مصنوعی، انتظار و نتیجه واقعی ثبت شود. تا تأیید محیط و کاربر نهایی، آمادگی بهره‌برداری بالینی اعلام نشود. تعیین تکلیف درخواست با مصرف ناقص و پاسخ نامشخص شبکه همچنان نیازمند سیاست و بررسی است.

## اصلاح پس از CI 46078428562
Build و ۱۲۱ تست عمومی و ۱۹ تست SQL قبلی موفق بودند؛ تست HTTP جدید در اولین GET بدون توکن، به جای 401 پاسخ 500 بدون متن گرفت. بررسی استاتیک نشان داد extension عمومی WithName از نام متد استفاده می‌کند و نام‌هایی مانند Capabilities/Stats/List در گروه‌های HEMO تکرار شده‌اند. نام‌های ۱۳۷ Endpoint HEMO با پیشوند HEMO.<Module>.<Method> یکتا شدند؛ verb/path، امضا، فیلتر توکن و مجوزها بدون تغییر ماندند. extension مشترک شرکت تغییر نکرده است. تست اکنون metadata تمام مسیرهای میزبان را پیش از شروع HTTP برای یکتایی نام و method/path بررسی می‌کند و exception غیرمنتظره را در خروجی تست ثبت می‌کند. علت دقیق 500 در لاگ اولیه قابل مشاهده نبود؛ نتیجه اصلاح با CI جدید باید تأیید شود.

## R03-02 — ادامه گردش HTTP بانک خون و تزریق
تست موجود IsolatedHttpAcceptanceTests به صورت یک گردش پیوسته و با همان پذیرش/درخواست تأییدشده گسترش یافته است. داده و اندازه‌گیری‌ها کاملاً مصنوعی‌اند؛ معیار بالینی نیستند. مراحل و نتیجه مورد انتظار:
| مرحله | نقش | مسیر مثبت / منفی |
|---|---|---|
| ترخیص | پذیرش | منع آمادگی ترخیص با درخواست فعال؛ وضعیت Active حفظ شود |
| تجهیز | کارشناس و بازبین فنی | ایجاد Hold؛ منع دریافت واحد و آزادسازی فاقد گواهی؛ سرویس و آزادسازی مستقل؛ ثبت دما |
| بانک | کارشناس و مسئول بانک | دریافت واحد؛ رد کد تکراری و رزرو قبل از بازرسی/آزمایش؛ بازرسی، آزمایش، رد RowVersion قدیمی، رزرو و Ready |
| حواله | مسئول بانک | عدم نمایش واحد رزروشده پیش از Ready؛ تطبیق شناسه و مچ‌بند؛ صدور، رد حواله تکراری و حذف از صف نامزدها |
| تزریق | پرستار و شاهد | دریافت؛ رد مچ‌بند اشتباه و شاهد یکسان؛ تأیید مستقل؛ منع شروع بدون T0 و تکمیل بدون End؛ پایش و تکمیل |
| کنترل نهایی | پرستار، مسئول بانک، مدیر آمار | تطبیق شناسه‌های پذیرش/درخواست/واحد، ثبت وقایع و پایش، Completed و Transfused، منع جزئیات مدیر آمار |
هیچ Seed، Migration، حساب کاربری یا زیرساخت دیگری اضافه نشده است. تعداد Factهای SQL ثابت است؛ سناریوها به همان Fact پیوسته افزوده شده‌اند. نتیجه CI مرحله دوم هنوز تأیید نشده؛ مرجوعی/توقف، واکنش، CAPA و کیفیت تکمیلی باید در مراحل بعدی یا پذیرش مستقل HTTP آزموده شوند. Login واقعی، Middleware شرکت، چاپ، UI و سرویس‌های خارجی همچنان خارج از پوشش این تست هستند.
