# R03 — تست HTTP ایزوله و پذیرش عملی
مبنای نسخه: backend main 0847c93a / frontend main d513ef5d. توسعه و merge R02 کامل است؛ این مرحله برای کشف ایرادهای اجرایی و پذیرش محیط آزمایشی است.

## مرحله اول: HTTP واقعی با SQL ایزوله
IsolatedHttpAcceptanceTests از کلاس‌های Endpoint واقعی web، Kestrel روی IP loopback و پورت آزاد، ثبت سرویس‌های Application/MediatR و Validatorهای واقعی، SQL Server و Migration و Seed کامل R02 استفاده می‌کند. رمزهای Seed و کلید امضای JWT فقط در حافظه تست و تصادفی هستند. توکن با UserService.SetTokenKey در رجیستری واقعی ثبت می‌شود؛ صدور JWT با کلید آزمایشگاهی است و Login/Captcha/OTP شرکت شبیه‌سازی نمی‌شود. Interceptor ممیزی آزمایشی جایگزین وابستگی Mongo/Log شرکت است؛ DispatchDomainEventsInterceptor واقعی حفظ شده. Exception handler موجود و کنترل‌های HEMO اجرا می‌شوند. Startup شرکت، زیرساخت مشترک، Dapper، اتصال به سرویس‌های بیرونی و middleware اختصاصی شرکت اجرا نمی‌شوند.
- شش endpoint Capabilities بدون Token باید 401 بدهند؛ JWT منقضی، TokenKey نامعتبر و Claim انقضای گذشته رد شوند.
- مدیر آمار هفت aggregate را دریافت کند؛ هفت درخواست فهرست و دو جزئیات رد شوند. CheckPagePermission برای داشبورد مجاز و پذیرش جدید غیرمجاز است. Header نقش خارج از Claim رد می‌شود.
- پذیرش مصنوعی: ایجاد، خواندن، ثبت تطبیق هویت، رد RowVersion قدیمی، ثبت سوابق، رد شماره پرونده تکراری.
- درخواست خون مصنوعی: ثبت پرستاری، ارسال، تأیید پزشک و خواندن توسط بانک خون.
- فقط Connection String آزمایشی loopback پذیرفته می‌شود؛ نام دیتابیس یکتا و بعد از تست حذف می‌شود. هرگز به DB شرکت اشاره نکند.
- CI موجود GitHub Actions، SQL Server 2022 موقت را آماده می‌کند. اجرای مستقل:
```bash
dotnet test tests/Hemo.Admission.Tests -c Release --filter "FullyQualifiedName~IsolatedHttpAcceptanceTests"
```
پیش‌نیاز HEMO_TEST_SQL با مقصد localhost و SQL Server آزمایشگاهی است. نتیجه این تست در PR ثبت می‌شود؛ قبل از مشاهده CI موفق، PASS محسوب نمی‌شود.
