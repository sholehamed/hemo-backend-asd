## وضعیت تحویل و مرز پذیرش
این بسته برای انتقال نسخه توسعه‌یافته HEMO-ASD به محیط آزمایشی مجاز شرکت است؛ نه اعلام بهره‌برداری بالینی. توسعه R02 و R03-01 تا R03-05 ادغام شده‌اند. R03-06 آماده‌سازی فنی و دروازه پذیرش را فراهم می‌کند؛ استقرار واقعی و امضای UAT بدون محیط/مسئول مجاز قابل تأیید نیستند.
- مبنای backend قبل از این PR: 82864ea984bf46dd8ab9f96a15f7944c8e7e623f (PR #34).
- مبنای frontend نهایی: b325b384789cb316bb50593a942647d28487772a (PR #37).
- SHA نهایی backend را پس از ادغام این PR از main ثبت کنید. Workflow مرورگر دقیقاً SHA فرانت فوق را checkout می‌کند و در CI موقت فقط apiUrl را به 127.0.0.1:18002 تغییر می‌دهد.
- دو فایل r02-active-route-contract.json در این دو مبنا یکسان‌اند؛ ۶۲ مسیر فعال با زیرساخت قبلی. زیرساخت و معماری مصوب: backend واحد .NET 9، EF Core/CQRS، Angular 19 و قالب و Identity موجود شرکت. [محدوده مصوب مالک](../HEMO_ASD_SCOPE_OVERRIDE_FA.md).

## پیش‌نیاز اجباری استقرار
1. مسئول زیرساخت شرکت محیط مجزا، مقصد DB و سرویس‌های وابسته، دسترسی امن، TLS، Origin/API URL و نحوه انتشار را تأیید کند. اتصال فعلی EF و Dapper وابسته به تنظیم موجود شرکت است؛ صرف تنظیم HEMO_TEST_SQL روی web واقعی اثری ندارد. پیش از اجرای web بررسی شود Startup به DB عملیاتی متصل نیست؛ web می‌تواند Migration و Seed اجرا کند. هیچ Connection String، Identity، CORS، middleware یا pipeline مشترک در این PR تغییر نمی‌کند.
2. DB آزمایشی اختصاصی، backup معتبر با آزمون restore، و تأیید Migrationهای موجود روی همان نسخه جداگانه. ابتدا تنها یک instance برای Migration بالا بیاید. در R03-06 هیچ Migration جدیدی وجود ندارد؛ معنی آن بی‌نیازی نصب اولیه از Migrationهای قبلی نیست.
3. رمزها، کلیدها و رشته اتصال از Secret Store یا روش مصوب شرکت؛ داده‌های مصنوعی فقط. هیچ حساب کاربری واقعی یا رمز آزمایشی در Git یا گزارش پذیرش ثبت نشود.
4. ساخت و بسته‌بندی روی Commit دقیق، ثبت SHA، CI URL، زمان، checksum و نام مسئول استقرار. بعد از تأیید مالک محیط نسخه زوج سازگار deploy شود؛ تغییر API URL فرانت مطابق مسیر مصوب شرکت، نه پورت تست CI.
## ساخت محلی بدون اجرای Startup شرکت
Backend (SDK 9):
```bash
dotnet build web/web.csproj -c Release
dotnet test tests/Hemo.Admission.Tests -c Release --filter "Category!=SqlServer"
dotnet publish web/web.csproj -c Release -o ./artifacts/hemo-backend
```
اجرای SQL تست تنها پس از تعریف HEMO_TEST_SQL روی SQL Server آزمایشگاهی مجاز است؛ تست نیازمند ساخت/حذف DB مستقل است. هرگز از DB شرکت استفاده نکنید.
```bash
dotnet test tests/Hemo.Admission.Tests -c Release --filter "Category=SqlServer"
```
Frontend (Node مطابق .node-version):
```bash
npm ci --no-audit --no-fund
npm run test:hemo
npm test -- --watch=false --browsers=ChromeHeadless
npm run build
```
خروجی فرانت dist/sakai-ng/browser؛ شرکت SPA fallback و مسیرهای واقعی API/Captcha را طبق زیرساخت موجود تنظیم کند. اجرای Build/Publish معادل deploy یا تست login نیست. Workflow مرورگر آزمایشگاهی در Actions و با checkout نسخه ثابت، SQL موقت، Chromium و داده ساختگی اجرا می‌شود؛ دستور npm run test:e2e در package.json فعلی وجود ندارد.

### ثبت نتیجه برای هر مورد
شناسه سناریو، نسخه دقیق backend/frontend، محیط، تاریخ UTC، مسئول/نقش، شناسه مصنوعی، انتظار، نتیجه واقعی، PASS/FAIL/NOT_RUN/BLOCKED، شناسه ایراد، مدرک بدون اطلاعات محرمانه و مسئول رفع. وضعیت نهایی باید جدا از نتیجه CI توسط مسئول محیط و مالک فرایند تأیید شود.
## Rollback و توقف انتشار
در صورت خطای Startup، افزایش خطاهای API، دسترسی غیرمجاز یا نقص معیار پذیرش، انتشار متوقف شود. زوج نسخه قبلی سازگار به‌صورت هماهنگ بازگردد؛ Restore پایگاه داده فقط بر اساس برنامه مصوب و ارزیابی تغییرات داده/Schema، نه حذف خودکار یا downgrade بدون بررسی. ابتدا دسترسی/امنیت و حفظ شواهد کنترل شود.
## موانع باز
- اتصال واقعی DB و زیرساخت مشترک شرکت خارج از اختیار این PR است؛ اجرای Startup روی مقصد نامعلوم ممنوع.
- Login/Captcha/OTP/Refresh و middleware واقعی شرکت با JWT آزمایشگاهی پوشش داده نشده‌اند.
- HTTP کامل برای مسیر توقف و مرجوعی هنوز جداگانه لازم است؛ تست‌های handler قبلی وجود دارند. تمام ۶۲ مسیر از UI واقعی آزموده نشده‌اند.
- سیاست کسری/مصرف ناقص، چاپ فیزیکی، سرویس‌های خارجی، بازبینی بصری انسانی و پذیرش مالک بالینی باز هستند.
- CI زوج نهایی باید سبز و PR در main ادغام شود. این شرط فقط تکمیل بسته فنی است، نه تایید استقرار و UAT.
